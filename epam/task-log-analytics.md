# Log Analytics System

## Task Description

Log analytics system collects and analyzes records generated by applications and services.

Given a minimum severity level and a list of log entries, count how many **valid** log messages were generated by each service.

Return a dictionary where:
- **keys** = service names
- **values** = number of unique valid logs for that service

Example shape:
```python
{"api": 2}
```

### Log Format

Each log entry is a string in the form:

```
<timestamp> <service> <severity>, <message>
```

- **Timestamp**: ISO 8601 (e.g. `2024-01-01T12:00:01+00:00`)
- **Service**: name of the service that produced the log
- **Severity**: one of `DEBUG`, `INFO`, `WARN`, `ERROR`, `CRITICAL`
- **Message**: free-form text after the comma

### Severity Order

```
DEBUG < INFO < WARN < ERROR < CRITICAL
```

### Requirements

1. **Filter** logs by the given `min_severity` (keep only logs whose severity is ≥ `min_severity`).
2. **Deduplicate** logs that share the same `(timestamp, service, message)`.
3. **Ignore** malformed / incomplete log entries (they must not raise errors).
4. Count the remaining unique valid logs **per service**.

### Example

**Input**
```python
{
  "logs": [
    "2024-01-01T12:00:01+00:00 api INFO, login",
    "2024-01-01T12:00:00+00:00 api INFO, login",
    "2024-01-01T12:00:03+00:00 api ERROR, failure"
  ],
  "min_severity": "INFO"
}
```

**Output**
```python
{"api": 2}
```

(The two INFO logs have different timestamps, so both are kept; both are ≥ INFO.)

### Constraints

- `1 <= len(logs) <= 100_000`
- Invalid log entries must not cause the program to crash
- Correctness is more important than performance

---

## Solution (Python)

```python
from collections import defaultdict
from typing import List, Dict


SEVERITY_ORDER = {
    "DEBUG": 0,
    "INFO": 1,
    "WARN": 2,
    "ERROR": 3,
    "CRITICAL": 4,
}


def analyze_logs(logs: List[str], min_severity: str) -> Dict[str, int]:
    """
    Count unique valid log messages per service, filtered by minimum severity.

    Args:
        logs: List of raw log strings.
        min_severity: Minimum severity threshold (DEBUG | INFO | WARN | ERROR | CRITICAL).

    Returns:
        Dictionary mapping service name -> count of unique valid logs.
    """
    if min_severity not in SEVERITY_ORDER:
        return {}

    min_level = SEVERITY_ORDER[min_severity]
    seen = set()  # (timestamp, service, message)
    counts = defaultdict(int)

    for entry in logs:
        try:
            entry = entry.strip()
            if not entry or "," not in entry:
                continue

            # Split header and message on the first comma
            header, message = entry.split(",", 1)
            message = message.strip()
            if not message:
                continue

            parts = header.split()
            if len(parts) < 3:
                continue

            timestamp, service, severity = parts[0], parts[1], parts[2]

            # Validate severity and apply filter
            if severity not in SEVERITY_ORDER:
                continue
            if SEVERITY_ORDER[severity] < min_level:
                continue

            # Deduplicate on (timestamp, service, message)
            key = (timestamp, service, message)
            if key in seen:
                continue

            seen.add(key)
            counts[service] += 1

        except Exception:
            # Silently ignore any unexpected parsing error
            continue

    return dict(counts)
```

### Usage Example

```python
logs = [
    "2024-01-01T12:00:01+00:00 api INFO, login",
    "2024-01-02T12:00:01+00:00 api ERROR, failure",
]
result = analyze_logs(logs, "DEBUG")
print(result)  # {"api": 2}
```

### Notes on Implementation

- Parsing is deliberately tolerant: any line that cannot be cleanly split into the expected fields is skipped.
- Deduplication key intentionally **excludes** severity (as specified by the problem).
- The solution uses a simple set for deduplication, which is sufficient given the constraint of ≤ 100 000 logs.
- Returns a plain `dict` (not `defaultdict`) so the result is JSON-serializable and matches expected test output.
